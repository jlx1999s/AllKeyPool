## Phase 1：Key 调度内核

状态：基础完成，后续可继续增强限流、健康和重试。

已交付：

- `ApiKeyRecord`
- `ProviderAdapter`
- `ProviderRegistry`
- `ApiKeyRepository` 接口
- `InMemoryApiKeyRepository`
- 从配置生成内存 Key 仓储
- `SchedulerService`
- `RoundRobinStrategy`
- `WeightedRoundRobinStrategy`
- 可用 Key 过滤：跳过 `disabled` 和 `cooling_down`
- Scheduler 装配进 Fastify app 实例
- 单元测试覆盖策略、仓储、调度服务和 Provider Registry

当前边界：

- Scheduler 只负责 key selection，不负责真实 HTTP 请求。
- Provider Registry 只提供注册和查找，不自动加载插件。
- In-memory 仓储适合开发和第一阶段测试，不是生产持久化方案。

## Phase 2：OpenAI 兼容代理

状态：基础完成。

已交付：

- `OpenAIAdapter` 骨架
- OpenAI-compatible `/v1/chat/completions`
- Provider 错误归一化
- 根据请求 `model` 匹配 pool/provider
- 从 pool 配置读取 strategy

- 使用 Provider Registry 查找 provider
- 上游成功响应透传
- 上游失败返回稳定 KeyPool 错误结构
- 429 / 5xx / 网络错误等 retryable provider error 换另一个 eligible key 重试
- key 候选耗尽时返回最后一次 provider 错误，不降级成 500
- `RetryPolicy`
- `ProviderRequestExecutor`
- Adapter 与路由层测试

当前边界：

- 重试执行已经从 proxy route 迁出到 core 层。
- 还没有 per-key TPM token bucket。
- 还没有 Health Event / Usage Record。
- 还没有 circuit breaker。
- 还没有 streaming chat completion。

## Phase 3.5：生产管理后台

状态：基础完成。

入口：

```text
GET /admin
```

已交付：

- 内置 HTML/CSS/JS 管理后台
- Admin Token 登录
- `GET /admin/api/state`
- `POST /admin/api/keys`
- `PATCH /admin/api/keys/:id/status`
- `DELETE /admin/api/keys/:id`
- `POST /admin/api/test/health`
- `POST /admin/api/test/chat`
- 查看 providers / pools / keys
- API Key 脱敏展示
- 运行时增配 OpenAI-compatible provider/key/pool/model
- 新增 key 时支持供应商预设选择
- 内置 OpenAI Compatible 和 MiniMax Official 预设
- Key 启用 / 禁用 / 删除
- Health 测试
- Chat proxy 测试
- 后台路由测试
- `/dev` 兼容跳转到 `/admin`

当前边界：

- 增配只写入内存，不持久化到 YAML 或数据库。
- 当前预设只覆盖 OpenAI-compatible provider，MiniMax Official 使用 `https://api.minimax.io/v1` 和 `MiniMax-M3`。
- 生产环境必须设置 `KEYPOOL_ADMIN_TOKEN`。
- 未设置 `KEYPOOL_ADMIN_TOKEN` 时，本地开发使用默认 token `keypool-admin-dev`。
- 暂无 Health Event / Usage Record 时间线。
- 暂无 RBAC、多用户、审计日志。

下一步建议任务：

1. 新增 `UsageRecorder` 接口和内存实现，并在面板展示最近请求。
2. 成功和失败都记录 usage。
3. 新增 `HealthEvent` 类型和内存记录。
4. 连续失败后将 key 标记为 `cooling_down`。
5. 新增 key 冷却恢复策略。
6. 将 RPM fixed window 演进为 token bucket 或 Redis 可替换实现。
7. 补充 TPM 统计入口。
8. 后台增加 usage / health event 时间线。
9. 支持安全持久化配置变更。
10. 支持生产级 RBAC 和审计日志。
