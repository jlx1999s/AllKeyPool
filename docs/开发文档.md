## Phase 1：Key 调度内核

状态：基础完成，后续可继续增强限流、健康和重试。

已交付：

- `ApiKeyRecord`
- `ProviderAdapter`
- `ProviderRegistry`
- `ApiKeyRepository` 接口
- `InMemoryApiKeyRepository`
- `KeyHealthService`
- 从配置生成内存 Key 仓储
- `SchedulerService`
- `RoundRobinStrategy`
- `WeightedRoundRobinStrategy`
- 可用 Key 过滤：跳过 `disabled` 和 `cooling_down`
- Scheduler 装配进 Fastify app 实例
- Provider 失败后累计 failureCount，第 1 次标记 `degraded`，第 3 次标记 `cooling_down`
- 进入 `cooling_down` 时写入 `coolingDownUntil`
- Scheduler 调度前自动释放已过期冷却 key，并将其恢复为 `degraded` 候选
- Provider 成功后清零 failureCount，并将 `degraded` key 恢复为 `healthy`
- 单元测试覆盖策略、仓储、调度服务和 Provider Registry

当前边界：

- Scheduler 只负责 key selection，不负责真实 HTTP 请求。
- Provider Registry 只提供注册和查找，不自动加载插件。
- In-memory 仓储适合开发和第一阶段测试，不是生产持久化方案。

已交付：

- `OpenAIAdapter` 骨架

- key 候选耗尽时返回最后一次 provider 错误，不降级成 500
- `RetryPolicy`
- `ProviderRequestExecutor`
- Adapter 与路由层测试

当前边界：

- 重试执行已经从 proxy route 迁出到 core 层。
- 还没有 per-key TPM token bucket。
- 还没有 Health Event。
- 还没有 circuit breaker。
- 还没有 streaming chat completion。

## Phase 3.5：生产管理后台

状态：基础完成。

入口：

```text
GET /admin
```

已交付：

- 内置 HTML/CSS/JS 管理后台
- 管理后台升级为生产控制台布局：顶部状态栏、侧栏导航、工作区、指标卡片、数据表和输出面板
- 管理后台支持桌面 / 平板 / 手机响应式布局
- 管理后台状态标签、空状态、表格滚动和焦点态视觉统一
- Admin Token 登录
- `GET /admin/api/state`
- `GET /admin/api/provider-presets`
- `GET /admin/api/usage`
- `GET /admin/api/health-events`
- `POST /admin/api/keys`
- `PATCH /admin/api/keys/:id/status`
- `DELETE /admin/api/keys/:id`
- `POST /admin/api/test/health`
- `POST /admin/api/test/chat`
- 查看 providers / pools / keys
- API Key 脱敏展示
- 最近请求 Usage 展示
- 最近 Health Events 展示
- 运行时增配 OpenAI-compatible provider/key/pool/model
- 新增 key 时支持供应商预设选择
- 新增 key API 支持 `presetId` 最小请求体
- 内置 OpenAI Compatible 和 MiniMax Official 预设
- Key 启用 / 禁用 / 删除
- Health 测试
- Chat proxy 测试
- 后台路由测试
- `/dev` 兼容跳转到 `/admin`
- `UsageRecorder` 接口
- `InMemoryUsageRecorder`
- `HealthEventRecorder` 接口
- `InMemoryHealthEventRecorder`
- Chat proxy 成功和最终失败 usage 记录
- Provider success/failure、key exhausted、手动 key status change health event 记录
- 连续失败自动将 key 标记为 `degraded` / `cooling_down`
- 冷却到期后自动释放 key 回到 `degraded` 候选
- Provider 成功自动恢复 `degraded` key
- 管理后台 key 表展示 `coolingDownUntil`

当前边界：

- 增配只写入内存，不持久化到 YAML 或数据库。
- Usage 当前只写入内存，不持久化到数据库。
- Health Events 当前只写入内存，不持久化到数据库。
- 当前预设只覆盖 OpenAI-compatible provider，MiniMax Official 使用 `https://api.minimax.io/v1` 和 `MiniMax-M3`。
- 生产环境必须设置 `KEYPOOL_ADMIN_TOKEN`。
- 未设置 `KEYPOOL_ADMIN_TOKEN` 时，本地开发使用默认 token `keypool-admin-dev`。
- 暂无 Health Event / Usage Record 聚合筛选。
- 暂无 RBAC、多用户、审计日志。

预设添加示例：

```json
{
  "presetId": "minimax-official",
  "id": "minimax-prod-1",
  "value": "sk-..."
}
```

下一步建议任务：

1. 为 Usage / Health Events 增加聚合统计和筛选。
2. 将 key/config/usage/health events 持久化到 SQLite。
3. 引入审计日志，区分用户操作和系统事件。
4. 将 RPM fixed window 演进为 token bucket 或 Redis 可替换实现。
5. 补充 TPM 统计入口。
6. 支持安全持久化配置变更。
7. 支持生产级 RBAC 和审计日志。
